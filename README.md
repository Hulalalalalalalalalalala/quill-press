# QuillPress

内容编辑与刊物发布。

需要Node.js 24 或更新版本。直接运行 TypeScript，不需要安装其他包。

查看命令帮助：

```sh
node server.ts --help
```

启动本地服务：

```sh
node server.ts serve --host 127.0.0.1 --port 8080 --data-dir data
```

打开 http://127.0.0.1:8080 查看首页。Ctrl+C 停止服务。`--data-dir` 指定本地业务数据目录，重启时继续使用同一目录。

首页是文章管理入口：填写标题、摘要（可选）和正文（纯文本，可多段），点击“保存草稿”即可保存一篇 `draft` 状态的草稿。保存成功后草稿立即按创建时间倒序显示在列表中（最新在前），表单清空；保存过程中按钮禁用，重复点击不会产生多篇草稿；保存失败时保留全部输入并显示原因。草稿仅用于管理，不会生成公开文章地址。

点击列表中某篇草稿的“编辑”按钮，会进入明确的编辑状态：表单上方显示“正在编辑草稿”标记，按钮变为“保存修改”，并提供“取消编辑”。进入编辑时会读取该草稿当前保存的完整内容（正文以读取到的全文为准，不会用列表中的摘要代替，也不会带入上一篇或新建表单的内容）。修改后点击“保存修改”，文章标识、创建时间和草稿状态保持不变，列表立即显示新的标题和摘要，不新增记录，仍按创建时间倒序排列，成功提示“修改已保存”。取消编辑不提交修改，文章不会被删除，页面回到可创建新草稿的状态。正文按原文保存与显示，换行、空行、中文、其他语言文字以及类似 HTML 的文本都不会被当作标记执行；标题仍按现有规则去掉首尾空白，摘要可以清空，空正文也允许保存。

同一篇草稿可能在两个页面中先后打开。若一个页面已保存修改，另一个页面基于旧内容提交时会被拒绝（409），不会覆盖已保存版本；页面会明确提示存在较新的内容，保留正在编辑的全部输入，并将“你正在编辑的内容”与“最新已保存的内容”分栏对照展示。只有明确确认“放弃修改并载入最新内容”后，才会重新载入最新内容继续编辑；冲突发生时不会自动重置表单或重试覆盖。选择“继续编辑”会保留当前输入，但再次保存仍会冲突。

接口：

- `GET /health` 返回服务状态和产品名称。
- `GET /api/articles` 返回文章列表，首次启动时为空：`{ "articles": [...] }`。
- `POST /api/articles` 创建一篇草稿。请求体为 JSON 对象，包含 `title`、`body` 和可省略的 `summary`（省略时保存为空字符串）。成功返回 `201` 和 `{ "article": ... }`，文章包含唯一字符串 `id`、`title`、`summary`、`body`、`status: "draft"` 以及带时区的 ISO 格式 `createdAt`。无效 JSON、非对象请求体、标题缺失或全为空白、字段类型不符均返回 `400` 和非空 `error`，不新增记录；读取或写入数据失败返回 `500` 且不会重置已有数据。
- `GET /api/articles/:id` 返回单篇草稿的完整内容：`{ "article": ... }`。文章不存在返回 `404` 和非空 `error`。
- `PUT /api/articles/:id` 更新一篇草稿。请求体为 JSON 对象，包含 `title`、`summary`、`body` 和 `updatedAt`（进入编辑时所依据的版本标记：文章的 `updatedAt`，没有 `updatedAt` 的旧草稿使用其 `createdAt`）。成功返回 `200` 和更新后的 `{ "article": ... }`，文章的 `id`、`createdAt`、`status` 不变，并写入新的 `updatedAt`。标题全为空白、字段类型错误、无效 JSON、缺少 `updatedAt` 返回 `400`；文章不存在返回 `404`；版本不一致（文章已被其他页面修改）返回 `409`，并在响应中附带当前已保存的 `article`；读取或写入失败返回 `500`。任何失败都不会改动已有文章，响应包含非空 `error`。
- 未知路径返回 404，已知路径不支持的方法返回 405（`Allow` 反映该路径实际支持的方法）。

```sh
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/articles
curl -X POST http://127.0.0.1:8080/api/articles \
  -H 'content-type: application/json' \
  --data '{"title":"第一篇草稿","summary":"可选摘要","body":"正文第一段\n\n正文第二段"}'
```
