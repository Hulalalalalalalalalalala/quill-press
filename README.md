# QuillPress

内容编辑与刊物发布。

需要Node.js 24 或更新版本。直接运行 TypeScript，不需要安装其他包。

查看命令帮助：

```sh
node server.ts --help
```

启动本地服务：

```sh
node server.ts serve --host 127.0.0.1 --port 8080 --data-dir data
```

打开 http://127.0.0.1:8080 查看首页。Ctrl+C 停止服务。`--data-dir` 指定本地业务数据目录，重启时继续使用同一目录。

首页是文章管理入口：填写标题、摘要（可选）和正文（纯文本，可多段），点击“保存草稿”即可保存一篇 `draft` 状态的草稿。保存成功后草稿立即按创建时间倒序显示在列表中（最新在前），表单清空；保存过程中按钮禁用，重复点击不会产生多篇草稿；保存失败时保留全部输入并显示原因。草稿仅用于管理，不会生成公开文章地址。

## 继续编辑草稿

草稿列表中每篇文章都有“编辑”按钮。点击后通过单篇接口读取这篇文章**当前已保存的标题、摘要和完整正文**填入表单（列表只显示摘要，正文一律以单篇接口返回为准），页面进入明确的编辑状态：表单出现“正在编辑草稿”标识（含创建时间与文章标识）、提交按钮变为“保存修改”、列表对应卡片标记“编辑中”。“保存草稿”的新建入口始终保留；未进入编辑态时提交仍是创建。

在编辑状态点击“保存修改”会更新同一篇草稿：`id`、`createdAt` 和 `status: "draft"` 保持不变，列表立即刷新标题和摘要且不会出现第二条记录，排序仍按创建时间倒序；成功提示明确说明修改已保存，保存后仍停留在编辑态可继续修改。标题按原规则去除首尾空白；摘要可以清空；空正文也允许保存；换行、空行、中文、其他语言文字以及类似 HTML 的文本均按原文保存与显示，不会执行其中任何标记。点击“取消编辑”不提交修改、不删除原文章，表单回到可创建新草稿的状态。

点击“编辑”时若表单有未保存内容，会先询问是否放弃；取消则不读取目标草稿，表单与编辑状态不变。确认或表单无修改后开始读取，读取期间标题、摘要和正文仍可继续输入。若等待期间没有任何新修改（改动后又恢复原值也不算），读取成功后照常载入目标草稿；只要有字段与开始读取时不同，读取成功后会先明确提示打开目标草稿将放弃这些新修改，由用户选择保留当前输入（表单和原编辑状态完全不变，当前输入也不会被当作目标文章的修改）或放弃输入并载入目标草稿。读取失败时保留全部当前输入和原编辑状态，显示失败原因，目标草稿不会被标记为正在编辑。仅打开草稿或取消切换不会保存任何内容。

### 版本冲突

每篇文章带有整数 `version`，每次保存成功后递增，编辑时以打开时读到的版本为基准提交。如果同一篇草稿在两个页面先后打开，其中一个页面已保存修改，另一个页面再基于旧内容提交时会被拒绝（`409`）。此时页面会明确提示存在较新的已保存内容，**保留表单中的全部输入**，并并排展示“你正在编辑的内容（未保存）”与“最新已保存内容”的标题、摘要、正文供对照。冲突不会重置表单或自动重试覆盖；只有用户点击“放弃当前输入并载入最新内容”明确确认后，才会载入最新内容继续编辑。点击该按钮时会通过单篇接口重新读取这篇草稿在本次读取时实际保存的版本（冲突对照显示之后若其他页面又有新的保存，以本次读取到的最新内容为准，不会把已过时的冲突对照当作最新内容）。读取期间表单不会提前清空，标题、摘要和正文仍可继续输入，页面明确显示正在载入，保存和重复载入暂时不可用。读取成功时，若等待期间没有任何新修改（改动后又恢复原值也不算）则直接载入；若有字段与开始读取时不同，会先说明载入将丢弃这些新修改，由用户选择保留当前输入（全部输入、原编辑对象和原版本基准都保持原状）或放弃并载入。若草稿已不存在或读取失败，显示失败原因并恢复可操作状态，保留全部当前输入及原编辑状态。保存请求进行中禁止重复提交，失败后按钮恢复可用并保留输入。

接口：

- `GET /health` 返回服务状态和产品名称。
- `GET /api/articles` 返回文章列表，首次启动时为空：`{ "articles": [...] }`。
- `POST /api/articles` 创建一篇草稿。请求体为 JSON 对象，包含 `title`、`body` 和可省略的 `summary`（省略时保存为空字符串）。成功返回 `201` 和 `{ "article": ... }`，文章包含唯一字符串 `id`、`title`、`summary`、`body`、`status: "draft"`、带时区的 ISO 格式 `createdAt` 以及从 `1` 开始的整数 `version`。请求体按整个 JSON 的 UTF-8 字节数计算上限（`5×1024×1024` 字节，含标题、摘要、正文及 JSON 本身），刚好达到上限仍可保存，超过上限返回 `400` 和说明超过允许大小的非空 `error`，且响应体可完整读取（Content-Length 与分块传输结果一致），不新增记录。无效 JSON、非对象请求体、标题缺失或全为空白、字段类型不符均返回 `400` 和非空 `error`，不新增记录；读取或写入数据失败返回 `500` 且不会重置已有数据。
- `GET /api/articles/:id` 返回单篇文章的完整内容（含正文与 `version`）；文章不存在时返回 `404` 和非空 `error`。
- `PUT /api/articles/:id` 更新已存在的草稿。请求体为 JSON 对象，包含 `title`、`summary`、`body` 和打开编辑时读到的非负整数 `version`。成功返回 `200` 和 `{ "article": ... }`，更新后的文章 `id`、`createdAt`、`status` 不变，`version` 递增。请求体超过 `5×1024×1024` UTF-8 字节上限时（规则同创建）返回可完整读取的 `400`，原文章（含标题、摘要、正文、标识、创建时间、版本）保持不变。标题全为空白、字段类型错误、`version` 缺失或类型不符、无效 JSON 均返回 `400`；文章已不存在时返回 `404`；当提交的 `version` 与当前已保存版本不一致时返回 `409`，响应体为 `{ "error": ..., "article": 当前已保存文章 }`，本次请求不改动已有文章。读取或写入失败返回 `500`。所有错误响应都带非空 `error`，且不会改动已有文章。
- 未知路径返回 404，已知路径不支持的方法返回 405（`Allow` 反映该路径实际支持的方法）。

旧数据目录完全兼容：由旧版本保存、没有 `version` 字段的草稿在读取时按版本 `0` 处理，可直接打开并编辑保存（首次更新后变为版本 `1`），不需要重新创建文章。

```sh
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/articles
curl -X POST http://127.0.0.1:8080/api/articles \
  -H 'content-type: application/json' \
  --data '{"title":"第一篇草稿","summary":"可选摘要","body":"正文第一段\n\n正文第二段"}'
curl http://127.0.0.1:8080/api/articles/<id>
curl -X PUT http://127.0.0.1:8080/api/articles/<id> \
  -H 'content-type: application/json' \
  --data '{"title":"修改后的标题","summary":"","body":"新正文\n\n<html>按原文保存</html>","version":1}'
```
