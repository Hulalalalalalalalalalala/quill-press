# chainview

chainview 是一个查看 X.509 证书信息的命令行小工具。当前版本提供：

- `chainview --version`：输出版本号；
- `chainview inspect <文件路径>`：查看一张本地 DER 编码 X.509 证书的基本字段。

## 构建与运行

```sh
cargo build --offline
./target/debug/chainview --version
```

输出：

```text
chainview 0.1.0
```

## 查看证书

```sh
./target/debug/chainview inspect cert.der
```

其中 `cert.der` 必须是 **DER 编码**的 X.509 证书文件（不支持 PEM 文本、
PKCS#7/PEM 证书集合，也不做签名验证）。文件必须恰好包含一张完整证书，
证书数据之后附有任何字节（包括空白、换行或另一张证书）都会被拒绝。

成功时证书信息输出到**标准输出**，每个字段单独一行，顺序固定：

```text
Subject: CN=example.com,O=示例公司,C=CN
Issuer: CN=Example CA,O=示例公司,C=CN
Serial Number: 0E8A4C2F9B17D603
Not Before: 2026-01-15T09:30:00Z
Not After: 2027-01-15T09:30:00Z
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `Subject` | 证书主体的完整可辨别名称（DN，RFC 4514 格式），保留全部名称属性及重复出现的属性；多值 RDN 以 `+` 连接。没有主体名称的合法证书该字段显示为空。 |
| `Issuer` | 颁发者的完整可辨别名称，格式与 `Subject` 相同。 |
| `Serial Number` | 证书序列号，以大写十六进制表示（不含 DER 整数的符号填充字节）。 |
| `Not Before` | 有效期开始时间，统一转换为 UTC，格式为 `YYYY-MM-DDTHH:MM:SSZ`。 |
| `Not After` | 有效期结束时间，格式同上。 |

名称中的每个 RDN（以 `+` 连接的一组属性）在 DER 中都是 SET OF，其成员必须
按各属性完整 AttributeTypeAndValue 编码的字节序升序排列：先比较外层标签，
再比较长度字节，最后比较内容字节。这一比较只针对原始编码，与 `CN`、`O` 等
显示名称、点分 OID 的文字形式以及解码后的属性值无关；未知属性和以 `#`
显示的非文本值适用同一规则。完整编码相同的成员允许相邻重复出现，单成员的
组天然满足要求。主体或颁发者名称中任一 RDN 不符合该顺序，即按损坏的 DER
证书拒绝（见下），查看时不会调整证书中的成员次序。

名称中的非 ASCII 内容（例如中文）按 UTF-8 原样显示，不会被转义或替换。
时间始终按 UTC 输出，不受运行机器所在时区影响。

名称属性值按其自身的字符串类型严格解码。`PrintableString`（标签 `0x13`）
只允许英文字母 `A`–`Z`、`a`–`z`、数字 `0`–`9`、普通空格，以及
`'`、`(`、`)`、`+`、`,`、`-`、`.`、`/`、`:`、`=`、`?` 这些字符；
其他字节一律非法，包括 `@`、下划线 `_`、制表符、换行、零字节以及
`0x80`–`0xFF`。值中只要出现一个非法字节，整张证书即按损坏的 DER 证书
拒绝：既不会删除或替换该字符后照常显示文本，也不会因为改用 `#` 十六进制
表示而被接受。这一限制只取决于值的类型：`CN`、`O` 等已知短名称属性和
以点分 OID 显示的未知属性一视同仁，主体名称和颁发者名称中的每个属性都
适用；未知属性以 `#` 引出完整原始 DER 十六进制时同样不能绕过该限制。
空的 `PrintableString` 内容沿用既有行为，仍然接受。其他字符串类型不受
影响：合法 `UTF8String`（标签 `0x0C`）中的中文或 `@` 等字符照常显示。

`BMPString`（标签 `0x1E`）的内容按大端序表示一串 16 位字符：字节数必须
为偶数，每个字符必须位于 U+0000–U+FFFF 的基本多文种平面内，且不得是
U+D800–U+DFFF 的代理项码位。单独的高代理项或低代理项，以及按 UTF-16
规则看似能组合成基本多文种平面之外字符的相邻代理项对，都属于非法内容。
任一属性值非法，整张证书即按损坏的 DER 证书拒绝：不会合并代理项、删除
字节或替换字符后继续显示。空的 `BMPString` 内容沿用既有行为，仍然接受。
这一限制同样只取决于值的类型：`CN`、`O` 等已知短名称属性和以点分 OID
加 `#` 十六进制显示的未知属性一视同仁，主体名称和颁发者名称中的每个
属性都适用；未知属性的十六进制展示不能绕过该检查。其他字符串类型不受
影响：`UTF8String` 或 `UniversalString`（标签 `0x1C`）中合法的基本
多文种平面之外的字符仍可正常查看。

`UniversalString`（标签 `0x1C`）的内容按大端序、每四个字节表示一个
Unicode 码点：字节数必须为四的倍数，每个码点必须位于 U+0000–U+10FFFF
之内，且不得是 U+D800–U+DFFF 的代理项码位。长度不完整（末尾余下不足
四个字节）、值中夹有单独的高代理项或低代理项（即使相邻出现、按 UTF-16
规则看似能组合成一个字符），或某个码点超过 U+10FFFF，都属于非法内容；
即使其余码点全部合法，整张证书也按损坏的 DER 证书拒绝：不会补齐或删除
字节、替换字符，也不会因为改用 `#` 十六进制表示而被接受。空的
`UniversalString` 内容沿用既有行为，仍然接受：已知短名称属性显示为空
文本，未知属性显示 `#1C00`。这一限制同样只取决于值的类型：`CN`、`O`
等已知短名称属性和以点分 OID 加 `#` 十六进制显示的未知属性一视同仁，
主体名称和颁发者名称中的每个属性都适用；未知属性的十六进制展示不能
绕过该检查。例如类型 `1.2.3.4` 的值是 U+1F600 时显示为
`1.2.3.4=#1C040001F600`（标签、长度和全部内容的大写十六进制，合法长
形式长度同样原样保留），同一个值位于 `CN` 中时则显示解码后的字符。
其他字符串类型不受影响。

属性类型没有已知短名称（如 `CN`、`O`）时，按 RFC 4514 用点分十进制
OID 标识该属性，等号之后以 `#` 引出该属性值完整 DER 编码（标签、长度
和内容）的大写十六进制表示。这里的 `#` 是编码标志，不是属性原本包含的
文字，因此不加转义反斜杠；即使值恰好是可读文本也一律按编码显示。例如
类型 `1.2.3.4` 的值是 UTF8String `abc` 时显示为
`1.2.3.4=#0C03616263`。同一名称中已知与未知属性可以混用、重复出现，
各自按自身类型决定表示形式。

已知短名称的属性，如果其值采用当前支持的字符串类型，仍显示短名称和
转义后的文本；如果采用的是其他合法、可被 DER 读取功能解析但没有文本
解码方式的类型（例如 `postalAddress` 的值是 SEQUENCE），则保留短名称，
等号后同样以 `#` 引出该值**完整 DER 编码**（标签、长度和内容）的大写
十六进制，长度字节按原始字节保留（包括合法长形式长度），不会只显示
内容或重新编码。例如属性 `2.5.4.17`（`postalAddress`）的值是仅含
UTF8String `abc` 的序列时显示为 `postalAddress=#30050C03616263`。这一
规则对 Subject 和 Issuer 同样适用，文本值、十六进制值和未知属性可以在
同一名称中混用，多值 RDN 仍以 `+` 连接。`#` 始终是编码标志，不加反斜杠。
十六进制形式只用于确实没有文本表示的值：已支持字符串类型的解码失败
（如 UTF8String 含非法 UTF-8）仍按损坏证书拒绝，不会改为十六进制后接受。

`inspect` 只展示解码得到的字段：它不验证证书签名，也不判断证书是否受信任；
即使证书尚未生效或已经过期，仍然可以正常查看。

### 扩展列表

v3 证书可以携带一个扩展字段（X.509 的 `extensions`），字段中的每个扩展都
必须能完整解码，但 `inspect` 不解释任何扩展值内部的业务含义：未知的扩展
OID（包括私有标识和含多字节编码数字部分的标识）、关键扩展（`critical` 为
真）以及空的扩展值都照常接受，扩展本身也不出现在五行输出中。

同一扩展列表中的每个对象标识符（OID）只能出现一次。是否重复只由完整的
扩展 OID 决定，与关键标志、扩展值的内容和长度均无关：两个条目完全相同，
或同一 OID 携带不同内容、不同关键标志，都属于损坏证书；重复项既可能相邻，
也可能夹在其他合法扩展之间。出现重复时不会选取其中一项、合并内容或删除
重复项后继续显示，而是整张证书被拒绝，错误信息给出重复 OID 的完整点分
十进制形式，例如 `1.2.3.4`、`2.5.29.14`。两个完整 OID 不同的扩展，即使
值和关键标志完全相同，仍允许共同出现。这一限制只作用于证书的扩展列表：
主体或颁发者名称中重复的名称属性不受影响，仍按原规则保留。

### 签名值位串

证书最外层的 `signatureValue` 是一个 BIT STRING，`inspect` 不会对其做密码学
验证（签名算法未知也不影响查看），但它的 DER 编码必须严格合法。位串内容的
第一个字节是最后一个数据字节中未使用位的计数，取值只能是 `0`–`7`：

- 计数为 `0` 时，所有数据位都有意义，最后一个字节的低位为 `1` 也照常接受；
  位串只含一个值为 `0` 的计数字节、没有任何数据时，继续沿用既有接受行为。
- 计数为 `1`–`7` 时，后面必须存在至少一个数据字节；在没有数据的情况下声明
  未使用位属于损坏编码，整张证书被拒绝。
- 计数为 `1`–`7` 时，最后一个数据字节低位中被声明为未使用的那些位必须全部
  为 `0`。例如声明 3 位未使用时，末字节为 `F8` 可以接受，为 `F9` 就拒绝。
  签名有多个数据字节时，这项要求只作用于最后一个字节：前面的字节以及末字节
  中实际使用的高位可以是任意值，不会因此拒绝正常编码。
- 位串连计数字节都没有、计数超过 `7`、字段类型不是 BIT STRING，或 TLV 编码
  被截断，同样按损坏的 DER 证书拒绝。

即使主体、颁发者、序列号和有效期都能正常读取，签名值位串编码损坏也会拒绝
整张证书：不会删除、补零或改写损坏内容后再显示。

### 失败与退出状态

- 成功：退出码 `0`，证书信息写入标准输出。
- 用法错误（缺少文件路径、提供多个路径、未知参数等）：退出码 `2`，
  标准错误输出正确用法：

  ```text
  Usage: chainview inspect <DER-FILE>
         chainview --version
  ```

- 文件不存在或无法读取（权限不足、路径是目录等）：退出码 `2`，
  标准错误输出 `chainview: cannot read certificate file '<路径>': <原因>`。
- 证书格式不正确（空文件、截断或损坏的数据、PEM 或其他 ASN.1 对象、
  证书后附带多余字节、主体或颁发者名称中某个多值 RDN 的成员未按 DER
  SET OF 顺序编码、主体或颁发者名称中的 `PrintableString` 含有非法字符、
  主体或颁发者名称中的 `BMPString` 长度为奇数或含有代理项码位、主体或
  颁发者名称中的 `UniversalString` 长度不是四的倍数、含有代理项码位或
  码点超过 U+10FFFF、签名值 BIT STRING 缺少计数字节、计数超过 7、声明未使用
  位却没有数据或最后一个数据字节的未使用低位不为零、扩展列表中同一扩展 OID
  出现多次等）：
  退出码 `2`，标准错误输出
  `chainview: invalid DER certificate: <原因>`，原因会指明出错的是主体
  还是颁发者名称；扩展 OID 重复时会给出该 OID 完整的点分十进制形式。

所有失败情况下标准输出保持为空，原因只写入标准错误。
